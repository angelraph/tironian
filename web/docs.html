Tironian docs

Everything you need to go from install to a small model answering your routine requests. If something here is unclear or wrong, open an issue.

Install

You need Hermes Agent 0.22.3 or newer, signed in to any model provider.

hermes plugins install angelraph/tironian
hermes plugins enable tironian

In Hermes Desktop you can also use the install link: Install in Hermes Desktop. Desktop shows what the plugin contains and asks before installing. To see the Tironian page, switch on its Desktop part in Capabilities, Plugins.

Plugins are off until you enable them, and the Desktop part is off until you switch it on. That is Hermes's rule, not ours, and a good one.

Your first report

hermes tironian report

or /tironian report in any session. Tironian reads your Hermes history read only, groups your requests into task families and shows how much of your work repeats and what it cost over the last 30 days. Nothing is sent anywhere and nothing is spent.

Your Tironian report · 47 sessions · 47 requests
64% of your requests are recurring tasks (30 requests).

Top task families:
  faa990c09  largest files · folder     10 req ·  6 good · needs 19 more good examples
  f7fe4b2c3  recent files · folder       8 req ·  8 good · needs 17 more good examples

A family becomes trainable at 25 good examples by default. Keep using Hermes normally: every good turn counts. You can speed things up with /tironian good after an answer you liked.

Your first model

  1. Set up the trainer once: hermes tironian trainer setup. It creates Tironian's own environment and installs the Modal client.
  2. Add your Modal token (see On Modal) and check it: hermes tironian trainer check. The check uses no compute.
  3. Train: hermes tironian train <family> --follow. You see the example counts and the cost before anything starts.
  4. Load the model in Hermes (see Loading a model), then test it: hermes tironian eval <student>.
  5. If it passes, try it in shadow mode: hermes tironian shadow <family>. When it agrees with your model often enough, hermes tironian promote <family> and switch on Let promoted students answer in the plugin settings.

On Modal

Modal rents GPUs by the second. Tironian uses your own account, so your data and your bill stay yours.

  1. Create an account at modal.com. The free Starter plan includes monthly credit (a small amount without a card, more with one).
  2. In Modal, open Settings, API Tokens, New Token.
  3. Paste the two values into Settings, Plugins, Tironian in Hermes Desktop, or add them to Hermes's .env:
MODAL_TOKEN_ID=ak-...
MODAL_TOKEN_SECRET=as-...

A run on an L4 GPU costs about $0.15 for a 1.7B model (my runs: 180 examples, about ten minutes, $0.14). max_usd_per_run (default $1.00) is enforced as a timeout on the GPU job, so a run can never cost more. The first run builds the training image, which adds a few minutes. See Cost for an estimate based on your own numbers.

On your own GPU

With an NVIDIA card, training is free and nothing leaves your machine.

hermes tironian trainer setup --local
hermes config set plugins.entries.tironian.settings.train_backend local

The local option installs PyTorch and the training libraries into Tironian's own environment (a few GB). A 1.7B model trains comfortably on 8 GB of GPU memory.

Dry run

hermes tironian train <family> --backend dry-run --follow

Runs the whole job pipeline, from dataset to status updates to a placeholder model file, with no compute at all. Useful for trying Tironian out and for its own tests. A dry-run model is not a real model and can't pass a test.

Loading a model

Trained models are saved as GGUF files under Tironian's data folder; hermes tironian students prints the paths. Tironian loads the model for you: if you run Ollama it registers it there, using the same prompt format it was trained on, and Hermes's own local model server works too. Tironian talks to http://127.0.0.1:8080/v1 by default and switches to Ollama's http://127.0.0.1:11434/v1 when only Ollama has the model. Any other OpenAI-compatible server works if you set student_endpoint.

Any OpenAI compatible server works too: Ollama, LM Studio or a llama.cpp server you run yourself. Set student_endpoint to its address.

Where files live

Everything is under <HERMES_HOME>/plugin-data/tironian/: the database (tironian.db), datasets/, jobs/, trained models in students/, and the trainer environment in sidecar/. Updating or removing the plugin keeps this folder, as Hermes intends for plugin data.

Troubleshooting

The report is empty

Tironian learns from sessions, so a fresh Hermes install has nothing to show yet. Use Hermes for a while, then run hermes tironian import.

A family never becomes trainable

Only good turns count. If your requests for one task are phrased very differently, they may form two smaller families; both will grow. /tironian good after answers you liked helps.

"Modal token missing" or "Token validation failed"

Check that both values are set and that the secret starts with as-. Run hermes tironian trainer check after changing them.

"the local model server doesn't list ..."

No local model server has the model yet. Install Ollama and run the test again, and Tironian will load it, or load the file into the server you use and set student_endpoint.

The model failed its test

That is the gate doing its job. The message says why (too few held-out steps, format errors or the lower bound). More data usually fixes it; train again later.

Nothing goes to the small model

Run /tironian why. Common reasons: routing is off, the family is still in shadow mode, or the request didn't match the family closely enough.

Uninstall

hermes tironian purge --yes
hermes plugins remove tironian

Purge first if you want the captured data gone; removing the plugin alone keeps its data folder. Delete your Modal token in Modal's settings if you no longer need it.
